# autodrive-dev-kit

**AIに開発を任せて回すための、道具一式。**

コードのレビューを人がやめても壊れないように、「誤りに気づく仕組み」と「記録の仕組み」を先に用意する。人がやるのは、**何を作るかの提示**と、**AIが止まった地点での判断**だけになる。

手法そのものの定義は [autodrive-dev-definition](https://github.com/hajimegane/autodrive-dev-definition) にある。**この文書を読むのに、定義を先に読む必要はない。**

---

## 何をしてくれるか

| | 中身 |
|---|---|
| **着手をまとめる** | 作業単位の確認・枝を切る・記録の紐づけ、を1つの操作で。飛ばすと止まる |
| **記録を自動で残す** | 止まった回数、やり直しとその原因、使ったトークン。**覚えていなくても残る** |
| **決めたことが守られているか判定する** | 記録が残っているか、任せる範囲の変更が履歴に残っているか、を機械が見る |
| **見え方を作る前に決める段取り** | 画面のあるものは、実装前に合意する（[docs/design.md](docs/design.md)） |

**逆に、してくれないこと。** アプリそのものは作らない。テストの中身も、画面の設計も肩代わりしない。これは**足場**であって、成果物ではない。

## 要るもの

| | |
|---|---|
| Node | 22.18 以上（型注釈をそのまま実行する） |
| 作業単位の置き場 | Linear（1ワークスペース）。API キーが要る |
| コードの置き場 | GitHub。CI を動かす |
| 配布先 | 任意。Cloudflare Workers での例が [agent-playground](https://github.com/hajimegane/agent-playground) にある |

**依存パッケージはゼロ。** `npm install` は要らない。

## 入れる

> **いまは手で繋ぐ。** 一式を配る `/init` は用意できていない。ここは現時点の正直な状態であり、**無いものを在るように書かない。**

1. このリポジトリを、開発するリポジトリの**隣**に置く

   ```
   作業場/
     autodrive-dev-kit/      ← これ
     あなたのアプリ/
   ```

2. 資格情報を作業場直下の `.env` に置く

   ```sh
   LINEAR_API_KEY=...        # 作業単位の取得・起票
   AUTODRIVE_CI_TOKEN=...    # 判定が Repo を読む。提出の読取を含めること
   ```

3. 記録の仕掛けを、**あなたのリポジトリの** `.claude/settings.json` に登録する

   ```json
   { "hooks": { "Stop": [{ "hooks": [{ "type": "command",
       "command": "<作業場>/autodrive-dev-kit/hooks/record-tokens" }] }] } }
   ```

   **参照実装側ではなく利用側に置く。** 判定器が読める場所にあることで、外されたときに気づける。

4. CI で判定を走らせる（[例](.github/workflows/verify.yml)）

## 使う

日常はこの4つで回る。

```sh
./bin/begin AUT-12 --repo あなたのアプリ    # 着手する
                                            # 作る
                                            # 提出する（PR）
                                            # 人が統合する
```

**着手は入口を通る。** 作業単位の確認・既定ブランチを最新にして枝を切る・記録の紐づけ先の設置を、まとめて行う。前提が崩れていれば**進まずに止まり、何をすればよいかを出す**。

```
あなたのアプリ はいま aut-11 にいる（既定ブランチは main）。
前の作業の枝の上から始めると、その提出が閉じている場合に変更が届かない。

次のどちらかを行うこと。
  - 前の作業が統合済みなら: git -C あなたのアプリ checkout main
  - まだ提出していないなら: 先にその作業を提出してから着手する
```

止まったこと・やり直したことを残すときは [ポート語彙](docs/ports.md) を使う。トークン消費は**自動で付く**ので、何もしなくてよい。

## 判定する

```sh
./verify --root <作業場>            # 全体を横断して判定
./verify --root . --scope self      # 1リポジトリの中だけ（各リポジトリの CI 用）
```

4つの「守られているべきこと」について、守られているか・守られていないなら何で代替しているかを出す。

```
[発効] テレメトリが記録されること
[未発効・代替あり] AIがこれらを無効化できないこと
    観測  403 — 非公開リポジトリに保護設定を置けないプラン
    代替  提出を経ることを規約で担保する。破られたかどうかは検出できる
```

**未発効は失敗ではない。** 失敗は「代替の記録が無い」ことと「判定できない」ことである。判定の全文は [docs/verify-criteria.md](docs/verify-criteria.md)。

## 注意

**本番の資格情報を、AIの手が届く場所に置かないこと。** 配布用のトークンは CI だけに持たせる。「本番データの破壊的操作・金銭の移動・外部への不可逆な公開」は、実績が積まれても緩めない。

**判定器を、判定が緩む方向に書き換えないこと。** 判定の変更には人の承認が要る。

**依存パッケージを足さないこと。** ゼロであること自体が、供給側の攻撃に対する守りになっている（[ADR 0001](docs/adr/0001-implementation-language.md)）。
